# Code review of the GlycA-stroke MR pipeline (10 November 2026)

Scope: every script of the v9 pipeline (00_setup.R, 01-11, run_all.R), line by line, plus independent re-implementation of the core
statistics in Python. Severity: HIGH = changes a reported number or hides an error, MEDIUM = latent error without current effect on
conclusions, LOW = maintainability.

## Findings and actions

| # | Severity | Finding | Action | Effect on reported results |
|---|---|---|---|---|
| 1 | HIGH | The cached AF instrument set (`af_instruments.rds`, 130 SNPs) was built by an early script that filtered the p-value column as character, so genome-wide significant SNPs whose p-value string began with 5-9 were dropped before pruning. The current `07_robustness.qmd` code (numeric p-value) gives 132 lead SNPs; the cache was reused and never rebuilt. | Stale caches removed; the cache is rebuilt by the script; `stopifnot()` checks that every cached p-value is numeric and < 5e-8; `tools/independent_raw_check.py` re-derives the lead SNPs from the raw file. | AF positive control and the product-of-coefficients estimate change slightly; GlycA to AF and all AF-exclusion analyses of the cardioembolic estimate are unchanged. Conclusions unchanged. |
| 2 | MEDIUM | `steiger_filtering()` does not recompute columns that already exist. The saved harmonised MEGASTROKE and GIGASTROKE files still carried `rsq.exposure`, `rsq.outcome`, `steiger_dir` and `steiger_pval` from an earlier run, so those two outcomes used stale Steiger values. | `add_steiger()` drops any existing Steiger columns before the call (`STEIGER_COLS`). | Directions agree under an independent recalculation (no disagreement for MEGASTROKE, GIGASTROKE, CES, SVS; one borderline large-artery instrument, rs7697204, differs between the exact function and the rough approximation used for the check). `steiger_pval` values in Tables S2, S3, S5d can change in the last digits. |
| 3 | MEDIUM | Figure S5 title and subtitle asserted "points the same way in all analyses" and "in every one", and group labels carried hard-coded SNP counts (41, 4, 3, 31). | All counts and statements are computed from the results; the title changes automatically if a condition fails. | None (values were correct). |
| 4 | LOW | Positional indexing of method rows (`het$Q_pval[2]`, `unique(S13$Outcome)[2]`) and string literals of method names repeated in four scripts. | `pick_method(tab, "ivw")`, `M`, `SET_LABELS`, `OUTCOMES$short` in `00_setup.R`. | None. |
| 5 | LOW | Locus definition, outcome labels and robustness-set labels were duplicated in three scripts and could drift apart. | Single definitions in `00_setup.R` (`define_loci()`, `LOCUS_ANCHORS`, `SET_LABELS`, `OUTCOMES`). | None (table S12b reproduced identically). |
| 6 | LOW | `check_harmonised()` added: stops on duplicated SNPs or non-finite effects and reports instruments whose allele frequency differs by more than 0.15 between exposure and outcome. | rs9270074 (MHC) is flagged in MEGASTROKE (EAF 0.84 in the exposure, 0.34 in the outcome; non-palindromic, alleles resolved by allele coding, so the estimate is unaffected). `eaf.exposure` added to Tables S2 and S3. | None. |
| 7 | LOW | Script numbering did not follow the run order (01, 02, 03, 08, 04, 07, 09, 06, 05, 11, 10). | Renumbered 01-11 in run order; token-dependent script last. | None. |
| 8 | LOW | Narrative blocks with typed numbers (for example "-0.021 to +0.016", "+0.077") inside the .qmd files, a reference to a checker script that was not shipped, NA placeholder keys in `manuscript_numbers.csv`. | Removed. Numbers appear only in generated output. | None. |
| 9 | LOW | Token script (`11_...`): the GIGASTROKE p-value column was not cast to numeric before filtering; clumping request was not pre-pruned. | Numeric cast, positional pre-pruning and subsetting to retained SNPs before Steiger filtering added. | Script is untested until it is run with a valid token. |
| 10 | LOW | `run_all.R` called `quit()` unconditionally on failure. | Stops with an error in interactive sessions; exit status 1 in batch. | None. |
| 11 | HIGH | The helper `pick(tab, method)` introduced in v10 has the same name as `dplyr::pick()` (dplyr >= 1.1). Inside `mutate()`/`transmute()` dplyr resolves the call to its own `pick()` and fails (\"Can't select columns with `hga`\"). First run of v10 on R 4.6.0 / dplyr 1.2.1 (11 Nov 2026): steps 01-06 passed, `07_robustness.qmd` computed every analysis and then stopped at the line that builds Table S14b, before writing Tables S14, S14b, S14c, `robustness_summary.rds` and Figure S5. | Helper renamed `pick_method()` in `00_setup.R`, `06`, `07`, `09`, `10` (no other change in the statistics). | None on numbers; the stop was a code error, not a statistical one. `codetools::checkUsage` and a parse check cannot detect this class of error. |
| 12 | LOW | `get_raw()` downloaded a raw file again when it was absent from `data/raw` of the pipeline folder although a copy existed in `../data/raw` (about 1 GB of duplicates). | `get_raw()` now returns the first existing copy in `DIR$raw`, then `../data/raw`; it downloads only if the file is in neither. | None. |
| 13 | MEDIUM | The Python multivariable code (`tools/mr_api_lib.py`, `mv_ivw`) divided the regression standard error by min(1, residual sigma), the rule of the univariable `mr_ivw`. TwoSampleMR 0.7.13 `mv_multiple` uses the unscaled regression SE. The rules agree for sigma > 1 (the 446-SNP BMI/smoking validation) and differ for sigma < 1; found by comparison with the R run of script 11 (GlycA + AF, cardioembolic, sigma 0.931: SE 0.0629 against 0.0586). | Rule corrected; Table S17 recomputed (`tools/recompute_s17.py`); Table S17c extended with 10 checks on the R dataset of the AF model (all within 1e-6). | Only the Python-computed rows with sigma < 1 changed (cardioembolic and MEGASTROKE cardioembolic AF-model estimates). The R cardioembolic row replaced the Python row: GlycA OR 0.874 (0.779-0.981), p = 0.022 instead of (0.773-0.989), p = 0.033. |
